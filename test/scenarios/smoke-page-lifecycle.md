# Smoke: ページのライフサイクル

新規ページ作成 → 編集 → 保存 → リロードで内容が復元されることを確認する基本シナリオ。
Claude in Chrome から実行することを想定。各ステップは「操作」と「検証」をペアで書き、
検証に失敗したら**即停止して、その時点の DOM / console / network を報告**すること。

---

## 前提条件

- ユーザーの Chrome に Memola ブックマークレット (`📋 Memola`) がブックマークバー上に登録済み。
- SharePoint (対象テナント) に既にログイン済みで、テスト用サイトのドキュメントライブラリにアクセス可能。
- `tools/` ディレクトリ配下のテスト用 SharePoint ページ URL は環境変数または以下で指定:
  - `TEST_SP_URL`: 例 `https://<tenant>.sharepoint.com/sites/<site>/SitePages/test.aspx`

## 実行ポリシー

- 1 ステップずつ実行し、検証結果を箇条書きで報告してから次へ。
- console に `error` レベルのログが出たら**即停止**して内容を貼ること (warn は継続)。
- 期待要素が **5 秒**以内に現れない場合は fail とし、`read_page` の出力を添えて報告。
- DOM 取得は原則 `read_page` (a11y ツリー) を優先。座標クリック (`computer`) は最後の手段。
- IME 入力が必要な場合は `form_input` で直接 value を入れず、後述の「テキスト投入の代替手段」を使う。
- 不明なモーダル / 確認ダイアログが出たら、内容を読み上げてからユーザーに確認 (勝手に「OK」しない)。

---

## Step 0: セットアップ

**操作**

1. `navigate` で `TEST_SP_URL` を開く。
2. ページが完全に読み込まれたことを確認 (SharePoint の本文領域が表示される)。
3. ブックマークバーの `📋 Memola` をクリックして bookmarklet を起動。

**検証**

- [ ] Memola の左ペイン (ツリー) が画面左に出現している (`read_page` で `tree` ロールが見える)。
- [ ] エディタ本文領域 (中央) が表示されている。
- [ ] console に未捕捉エラーが無い。

---

## Step 1: 新規ページを作成

**操作**

1. 左ペインの「新規作成」ボタンをクリック (ラベルまたは `aria-label` で特定)。
2. タイトル入力欄にフォーカスが移ったことを確認。
3. タイトルとして `smoke-${ISO日付}-${ランダム4桁}` を入れる (例 `smoke-2026-05-05-3a7f`)。
   - 入力は ASCII のみなので `form_input` で OK。

**検証**

- [ ] 左ペインのツリーに作成したページが追加され、選択状態になっている。
- [ ] エディタ本文がそのページに切り替わり、本文は空 (またはテンプレ初期状態)。
- [ ] network に新規ページ作成系の API (`/_api/.../pages` or 内部 endpoint) が成功 (2xx) で飛んでいる。

---

## Step 2: 本文を編集

**操作**

1. エディタ本文の最初の行をクリックしてキャレットを置く。
2. 以下 3 行を投入する:
   - `Smoke test paragraph`
   - `- list item one`
   - `- list item two`

**テキスト投入の代替手段** (IME 安定化のため):

- 純 ASCII の場合: `form_input` または `computer` のキーボード入力で OK。
- 日本語を含む場合: `javascript_tool` でエディタの API を直接呼ぶ。例:
  ```js
  // 例: グローバルに公開されている想定の API があれば
  window.__memola?.editor?.insertText?.('テスト本文');
  ```
  公開 API が無い時はこのシナリオでは日本語入力をスキップし、別シナリオに切り出すこと。

**検証**

- [ ] DOM 上に上記 3 行のテキストノードが見える (`read_page`)。
- [ ] 箇条書き 2 行が `<ul><li>` 構造になっている (Markdown ショートカットが効いている)。
- [ ] 「未保存」インジケータ (タイトルバーの `*` 等) が出ている。

---

## Step 3: 保存

**操作**

1. `Mod+S` (mac は `Cmd+S`、win は `Ctrl+S`) を送出。
   - ショートカットは `keymap.ts` 経由なので、必ず**エディタ本文にフォーカスがある状態**で送る。

**検証**

- [ ] トースト or 表示で「保存しました」相当のフィードバックが出る。
- [ ] network に保存系 API (PUT/POST) が成功で飛んでいる (`read_network_requests`)。
- [ ] 「未保存」インジケータが消えている。
- [ ] console に error が出ていない。

---

## Step 4: リロードして復元を確認

**操作**

1. `navigate` で同じ `TEST_SP_URL` を開き直す (または `location.reload()`)。
2. SharePoint ページ読み込み後、再度 `📋 Memola` を起動。
3. 左ペインから Step 1 で作ったページを選択。

**検証**

- [ ] ページタイトルが Step 1 で付けた名前と一致。
- [ ] 本文 3 行が Step 2 と同じ順序・構造で復元されている。
- [ ] 「未保存」インジケータが出ていない (= ローカルとサーバーが一致)。

---

## Step 5: クリーンアップ (任意)

> 失敗で止まった場合はクリーンアップせずユーザー報告で終わる。成功時のみ実施。

**操作**

1. 作ったページを左ペインから削除 (右クリックメニュー or 削除ショートカット)。
2. ゴミ箱 / Trash UI から完全削除 (もしあれば)。

**検証**

- [ ] ツリーから消えている。
- [ ] network に削除系 API が成功で飛んでいる。

---

## 報告フォーマット

実行終了時 (成功・失敗問わず) は以下の形で報告:

```
## 結果: [PASS / FAIL at Step N]

### Step ごとの結果
- Step 0: ✅ / ❌  (一言所感)
- Step 1: ...

### 失敗時の追加情報
- 直前の操作: ...
- 期待した DOM/状態: ...
- 実際に観測した DOM/状態: ...
- console errors: ...
- network 異常: ...
```

---

## このシナリオの既知の弱点

Claude in Chrome では以下が苦手なので、このシナリオではあえて触れていない:

- **IME 経由の日本語入力** (composition イベント) — `editor2-state.test.ts` 等の単体テストでカバー。
- **ブロック DnD による並び替え** — キーボードショートカットがあれば別シナリオで、無ければ単体テスト側でカバー。
- **ピクセル単位の visual regression** — 必要なら `preview_screenshot` を撮って人間レビュー。
